# Build 32: 負荷試験基盤とシードデータ

## やること

- 負荷試験の道具の導入（k6）と、試験用の設定（基盤セットアップ）
- 1年後の規模のシードデータ生成: ユーザー10万、投稿500万、いいね5,000万、フォロー500万（フォロワー5万人以上の人気ユーザーと、フォロー5,000人のユーザーを含む）、画像つき投稿の割合。`docker compose` 上の PostgreSQL に投入でき、本番相当の構成にも使える
- シナリオ（スクリプト）:
  - 読み取り: グローバルフィード・タイムライン・ユーザーページ・単体ページ・検索（短い語、ヒット数が非常に多い語、数十〜数百語の AND / OR、短い語を多数 OR で結んだ長いクエリ）。ピーク時の読み取り毎分500件・書き込み毎分50件の混合
  - 書き込み: 投稿・いいね・フォロー
  - 急増: 単体ページ（画像つき）に毎分5,000件を30分、同時に他機能が動く
  - 画像: 一覧由来の画像リクエスト（秒間約170件の目安）と、認可つき配信、304 の割合
- 計測の出力形式（p95、エラー率、DB・ECS の使用率）とレポートの雛形
- 本ビルドでは、基盤・シード・シナリオを用意し、小さな規模で動作確認する。本番規模の実測と判定は build-33

## やらないこと

- 本番規模での実測と判定、レポートの確定（build-33）
- 本番環境への負荷の印加（試験環境の用意は build-33 の手順に従う）

## 対応する受け入れ基準

なし（非機能要件: 性能・急増への耐性の検証基盤）

## 受け入れ基準

- [ ] シードデータ生成のコマンドで、指定した規模のデータが投入できる（小さな規模で動作確認し、所要時間と投入量の目安を記す）
- [ ] 上記のシナリオが k6 のスクリプトとして定義され、小規模で実行できる
- [ ] 計測結果の出力形式とレポートの雛形がある
- [ ] 評価に必要な機能（フィード・タイムライン・ユーザーページ・単体ページ・検索・フォロー・公開範囲設定・申請・フォロワー・画像）が揃った状態を前提にしている（依存ビルドが完了済み）
