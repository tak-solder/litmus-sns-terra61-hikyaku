# Build 18: グローバルフィード・タイムラインAPI

## やること

- 一覧 API で共通に使う部品: 投稿の一覧項目（本文・画像 URL・投稿日時・投稿者名・合計いいね数・`is_liked_by_me`）のシリアライザと、id のキーセットページング（新しい順、1回最大20件、続きを取得できるカーソル）。いいね済み判定はページ内の投稿 ID をまとめて1クエリで取得する（N+1 を避ける）。閲覧権限の共通条件（build-11）を使う
- `GET /api/feed`: グローバルフィード。ゲストも閲覧でき、`is_liked_by_me` はすべて false。非公開ユーザーの投稿は本人とフォロワーにだけ含める
- `GET /api/timeline`: タイムライン。承認済み（accepted）のフォロー先と自分の投稿のうち、削除されていないものだけを `(author_id, id desc)` のインデックスで取得する。申請中（pending）の相手の投稿は含めない。誰もフォローしていなければ自分の投稿だけ。ゲストは 401
- 書き込み直後の自分の投稿が先頭に出ることを結合テストで確認する

## やらないこと

- ユーザーページの一覧（build-19）、検索（build-21）
- Web の画面（build-22）
- 読み取りレプリカの利用（権限判定を含む読み取りは常にプライマリ）

## 受け入れ基準

- [ ] グローバルフィードが新しい順に最大20件ずつ返り、続きを取得できる。各項目に本文・画像 URL・投稿日時・投稿者名・合計いいね数・`is_liked_by_me` が含まれる
- [ ] ゲストの `is_liked_by_me` はすべて false。非公開ユーザーの投稿はゲストに出ず、本人とフォロワーには出る
- [ ] タイムラインは accepted のフォロー先と自分の投稿だけで、フォローしていない人・申請中の相手の投稿は出ない。承認されると出るようになる
- [ ] 削除した投稿はどちらの一覧にも出ない。公開範囲の変更が即時に反映される
- [ ] ゲストのタイムラインは 401。投稿した内容が自分のタイムラインとグローバルフィードの先頭に出る
