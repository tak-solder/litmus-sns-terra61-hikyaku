# Build 20: 検索クエリ解析ライブラリ

## やること

- 検索入力を解析する純粋なライブラリ（`apps/api/src/search/`）。入力は文字列、出力は検索条件の構文木（または「条件が成り立たない」エラー）
  - 空白（全角空白を含む）で区切った語は AND
  - 語の前の `-` は除外
  - 語の間の `OR` は、どちらかを含む
  - `"..."` で囲んだ語句は、空白を含めてその並びのとおりに含む（フレーズ）
  - 正規化: NFKC 正規化 + 小文字化（投稿保存時の `search_text` と同じ関数を共有する）
  - 空・空白のみ、除外の語だけなど、条件として成り立たない入力は理由の種別つきで拒否する
  - 語数・文字数に任意の上限は設けない
- 構文木を LIKE 条件（エスケープ済みの `%` `_` `\` とパラメータ）に変換する部品（SQL への組み立て。DB へは問い合わせない）。同じ語の重複は正規化後に除く
- テスト: US-10.2、10.5〜10.10 の例（「ＡＢＣ」で「abc」、「ｶﾀｶﾅ」で「カタカナ」、AND、除外、OR、フレーズ、不成立の入力）と、短い語を数百個 OR で結んだクエリ、LIKE のメタ文字を含む入力

## やらないこと

- 検索 API・DB への問い合わせ・pg_bigm のインデックス（build-21）
- Web の画面（build-27）

## 対応する受け入れ基準

- US-10.2, US-10.5, US-10.6, US-10.7, US-10.8, US-10.9, US-10.10

## 受け入れ基準

- [ ] 全角半角・英字の大小・カタカナの全角半角を区別せず一致する条件が組み立てられる
- [ ] AND / 除外 / OR / フレーズが仕様どおりの構文木になる
- [ ] 空・空白のみ・除外のみなど、成り立たない入力は理由つきで拒否される
- [ ] 語数・文字数に上限が無く、数百語の入力でも解析できる
- [ ] LIKE のメタ文字がエスケープされ、値はパラメータ化される
