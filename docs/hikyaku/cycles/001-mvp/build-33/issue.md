# Build 33: 性能・費用・画像処理の検証とREADME

## やること

- 検証の実施と結果の記録（`docs/verification/`）。build-32 の基盤で、1年後の規模のデータを投入した環境に対して実測する:
  - 一覧・単体ページの p95 1秒、検索の p95 3秒、書き込みの p95 1秒（ピーク時の読み取り毎分500件・書き込み毎分50件）
  - 単体ページ（画像つき）に毎分5,000件が30分続く間の、表示の継続と他機能への影響
  - 画像リクエストごとの認可を含む配信の負荷（一覧由来で秒間約170件の目安）と、ECS・転送の費用見積もり。飽和する場合は画像配信の専用サービスへの分離を評価する
  - 検索の負荷保護: 数十から数百語の AND / OR、短い語を多数 OR で結んだ長いクエリ、ヒット数が非常に多い語での p95 3秒と他機能への影響
  - 費用: build-28〜30 の見積もりと実測をもとに、運用開始時点の AWS 費用が月額300米ドル以内かを判定する
- 画像のメタデータ除去の検証: JPEG / PNG / GIF / WebP のそれぞれで、ブラウザで表示できる、位置情報などが残っていない、回転ありの JPEG が正しい向きで表示される、ICC プロファイルのある画像の色が変わらない、GIF と WebP のアニメーションが除去前と同じフレーム数・ループ回数で動く。5MB 近い画像と画素数の非常に大きい画像でメモリ使用量と処理時間が問題にならないこと
- 要件を満たせなかった項目は、満たせない条件と対策案を結果に記し、完了の案内で報告する。入力の制限などで要件を緩めて合わせることはしない
- README を完成させる: プロジェクトの概要、`docker compose up` での起動手順、Web UI と API の URL、メールキャッチャー（Mailpit）の URL、テスト・マイグレーションの実行方法、API 仕様書（OpenAPI）の場所、インフラのコードの使い方、検証結果へのリンク
