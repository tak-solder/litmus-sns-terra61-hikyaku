## 改善提案

### R-1: ビルド分割は、依存先が先に登録できる順（トポロジカル順）で番号を振る
- **状況**: Step 5b で33ビルドの分割案を作ったとき、関連する機能をまとめた番号で案を作ったため、旧 build 10・11 が番号の大きい旧 build 14 に依存する案になった。`tasklist add` は buildID を `max(既存) + 1` で採番し、依存先が既に存在しないと登録できない
- **指示内容**: 依存が番号の大きいビルドを指していることを指摘され、登録時に依存先が存在する順序で登録できることの確認を求められた
- **提案**: 分割案を作る時点で、番号順が依存順（各ビルドの依存はすべて自分より小さい番号）になっているかを確認する。依存を持つ機能は、依存先を先に採番する
- **優先度**: Should
- **対象**: workflow
- **具体案**: `instructions.md` に追記する。「architect のビルド分割では、案の段階で各ビルドの依存が自分より小さい番号だけを指すことを確認する。`tasklist add --dry-run` は依存先が未登録だと使えないため、33ビルドのような大きな分割では案の表で確認し、G6 の提示にも依存が小さい番号だけであることを明示する」

### R-2: user-stories に無い入力上限は設計に入れない。保護は拒否ではなく負荷対策で行う
- **状況**: Step 4c の design-delta で、検索語の文字数・語数や画像の画素数に任意の上限を設けた。user-stories にはどちらの上限も無く、受け入れ基準が許す有効な入力を拒否していた
- **指示内容**: 任意の上限で有効な検索・画像を拒否しない設計にし、負荷の保護は要件を満たす方法を検討して、満たせなければ報告するよう指示された
- **提案**: 設計で入力に上限を足す前に、user-stories の受け入れ基準とスコープに根拠があるかを確認する。根拠が無い場合は、拒否ではなく負荷対策（接続プール、タイムアウト、レート制限、オートスケール）を設計し、検証計画で実測する
- **優先度**: Must
- **対象**: doc:conventions
- **具体案**: conventions に追記する。「要件に無い入力上限（文字数・語数・画素数など）を設けない。負荷の保護は、専用の接続プール、`statement_timeout`、レート制限、オートスケールで行い、満たせない場合は要件を緩めずに報告する」

### R-3: 権限判定を含む読み取りは増強方法まで一貫させる
- **状況**: Step 4b の ADR に、将来の増強方法として読み取りレプリカを書いたが、design-delta では権限判定を含む読み取りを常にプライマリに限定していた。ADR と design-delta で互いに矛盾した
- **指示内容**: 即時反映を保つ増強方法に ADR を修正するよう指示された
- **提案**: ADR の「トレードオフ」に将来の増強策を書くときは、design-delta と他の ADR が定める制約（即時反映、プライマリ読み取りなど）と矛盾しないかを照合する
- **優先度**: Should
- **対象**: 記録のみ
- **具体案**: 該当なし（architect の手順内の確認で、この設計に固有の誤りだったため記録にとどめる）

## リポジトリ固有の学び（L-N）

### L-1: `tasklist add` は依存先が先に登録されていないと失敗し、buildID は `max(既存) + 1` で振り直せない
- **再現条件**: 空の tasklist に、`--deps` に未登録の buildID を指定して `tasklist add` する。または、`--dry-run` で複数ビルドを連続して差分確認しようとする（dry-run は書き込まないので、後続ビルドが依存先を解決できない）
- **影響**: 33ビルドのような大きな分割では、全体の差分を `--dry-run` で一度に示せない。番号の順序が依存順でない案は、登録時に初めて失敗が分かり、採番し直しが要る
- **回避策**: 案の段階で番号を依存順に振っておく。全体の確認は案の表で行い、書き込み時にスクリプトが依存の存在と循環を検証する
- **判明したビルド**: 設計フェーズ（Step 5b）
- **判明日**: 2026-10-31

### L-2: 非対話セッションでは、複合コマンドやスクリプトの実行が承認待ちになり拒否される
- **再現条件**: 許可リストに無い形（`bash script.sh`、`;` で `echo` などを続けた複合コマンド、`>/dev/null` を含む連鎖）を Bash で実行する。許可リストにある `node ".../hikyaku.mts" ...` 単体、またはそれらを `&&` で連ねた形は通る
- **影響**: 承認画面が無いため自動で拒否され、同じ操作は再試行できない。BP 見積もりのように多数のコマンドを一括で回したい作業は、1つずつの呼び出しに分ける必要がある
- **回避策**: `hikyaku.mts` の呼び出しを単体で、または `&&` の連鎖で実行する。出力の整形が必要なら `| tail` や `| head` を使う
- **判明したビルド**: 設計フェーズ（Step 5b）
- **判明日**: 2026-10-31
