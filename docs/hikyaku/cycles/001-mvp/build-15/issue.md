# Build 15: 画像の形式検証・メタデータ除去ライブラリ

## やること

- `packages/` ではなく `apps/api/src/image/` に、画像の検証とメタデータ除去の純粋なライブラリを作る（画像をデコード・再エンコードしない。入力は Buffer、出力は検証結果と除去後の Buffer）
- 検証: マジックバイトとヘッダの構造で JPEG / PNG / GIF / WebP を判定する。5MB を超えるもの、4形式以外、ヘッダを解釈できないものは拒否する（理由の種別を返す）。画素数の上限は設けない
- メタデータ除去（design-delta「投稿・検索・画像」の仕様どおり）:
  - JPEG: APP1（Exif / XMP）、APP13（IPTC）、コメントを除去し、EXIF の向き（Orientation）だけを持つ最小の EXIF に書き換えて残す。JFIF、ICC（APP2）、Adobe（APP14）は残す
  - PNG: `tEXt` / `zTXt` / `iTXt` を除去し、`eXIf` は向きだけにする。`iCCP`、`gAMA`、`cHRM`、`sRGB`、`pHYs`、アニメーション用チャンクは残す
  - WebP: EXIF / XMP を除去し、向きは最小の EXIF として残す。`ICCP`、`ANIM` / `ANMF` は残し、`VP8X` のフラグを内容と整合させる
  - GIF: コメント拡張・プレーンテキスト拡張・XMP のアプリケーション拡張を除去し、グラフィック制御拡張と `NETSCAPE2.0`（ループ回数）は残す
- 検証用の画像フィクスチャ（4形式。GPS つき JPEG、回転あり JPEG、ICC つき、アニメーション GIF・WebP・APNG、5MB 近いもの、壊れたもの、画素数の大きいもの）
- テスト: 除去後に（a）構造が有効、（b）位置情報などが残っていない、（c）向きが保たれる、（d）ICC が同一、（e）アニメーションのフレーム数・ループ回数が除去前と同じ、であることを確認する

## やらないこと

- S3 への保存、アップロード API、配信（build-16）
- サムネイル生成・リサイズ（スコープ外）
- ブラウザでの目視による表示確認（build-33 の検証で行う）

## 対応する受け入れ基準

- US-4.6

## 受け入れ基準

- [ ] JPEG / PNG / GIF / WebP 以外、5MB 超、壊れた画像が拒否され、理由の種別が返る
- [ ] 4形式のそれぞれで、除去後の画像が有効な構造を保ち、位置情報などのメタデータが残らない
- [ ] 回転あり JPEG の向き、ICC プロファイル、アニメーション（フレーム数・ループ回数）が除去前後で保たれることをテストで確認する
- [ ] 画素数が非常に大きい画像でも、処理時のメモリが 5MB 程度の読み込みに収まる（デコードしない）
