# 投稿検索は PostgreSQL の pg_bigm と正規化列で実装する

- **決定**: 投稿保存時に本文を NFKC 正規化して小文字化した列 `search_text` を持ち、pg_bigm の GIN インデックス上で LIKE により部分一致検索する。AND / OR / 除外 / フレーズはクエリ組み立て側で LIKE の論理式に変換する。
- **文脈**: US-10 は部分一致、英字の大小・英数字・カタカナの全角半角の同一視、AND / OR / 除外 / フレーズを要求する。1年後は投稿500万件で p95 3秒以内。運用開始時の費用は AWS 月額300米ドルが目安。
- **検討した案**:
  - 案A: pg_bigm（2-gram の GIN）。RDS PostgreSQL の拡張機能として使える
  - 案B: pg_trgm（3-gram）
  - 案C: OpenSearch
- **採用理由**: DB が1つで済み追加コストがほぼ無い。NFKC 正規化だけで「ＡＢＣ」→「abc」「ｶﾀｶﾅ」→「カタカナ」の同一視が満たせる。日本語の1〜2文字検索も 2-gram で扱える。案B は日本語の短い語に弱く、案C は常時コストが目安を圧迫し、DB との同期も要る。
- **トレードオフ**: ヒット数が非常に多い語では「新しい順」の並べ替えと可視性フィルタで走査量が増え、遅くなりうる。RDS の拡張機能に依存するため、移行先を選ぶ。正規化列の分だけ保存容量が増える。1年後の規模での p95 は実測で検証する（検証で満たせなければ案Cへ移行を検討する）。
- **影響範囲**: `posts` テーブル（`search_text` 列と GIN インデックス）、検索 API、投稿作成時の正規化処理、compose の PostgreSQL イメージ（pg_bigm を含める）。
